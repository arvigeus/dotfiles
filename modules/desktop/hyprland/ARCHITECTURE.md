# Desktop session implementation

Desktop portals use GTK for file dialogs and Settings, and Hyprland for screenshots
and screen sharing. See [appearance integration](../../look-and-feel/ARCHITECTURE.md)
for shared palette/mode propagation. Troubleshooting commands and shortcuts are in
[README.md](README.md).

Desktop packages are native `packages` declarations in their owning modules,
without archinstall's Desktop/Hyprland presets. Those presets bundle a second
launcher, notification daemon and PolicyKit agent. Logind supplies seat access;
the polkit module installs its dependency and this module enables hyprpolkitagent.

## Configuration loading

`hyprland.lua` loads each component with Hyprland's `require()`, which searches
`~/.config/hypr/`, records errors per file, watches the resolved files (including
symlink targets) and re-runs them on reload. Optional files use
`pcall(require, ...)`: `input-method` from the input-method module, then in
`monitors.lua` the selected host's `host-monitors` and the user-owned `displays`
generated by the display helper for the current monitor set, so saved layouts
override host defaults.
Settings equal to Hyprland's built-in defaults are omitted. Hyprland itself imports
its environment into systemd and notifies UWSM of readiness; `XCURSOR_SIZE` is
declared in `environment.d` because X11 clients otherwise choose their own size.

`appearance.lua` enables window motion blur with Hyprland's default sample count.
`input.lua` combines detached pointer focus (`follow_mouse = 2`) with
`swallow_focus_click`, so focus clicks do not reach applications. It disables
`binds.drag_center_window` to preserve the relative grab point when dragging a
tiled or fullscreen window into floating mode. Spring curves use `damping`.

Automatic reload starts on the first `IN_CLOSE_WRITE` of a watched file and then
re-creates every watch, discarding events still queued for the old ones. A burst
of writes to several files therefore loads whichever versions existed at that
first reload; 0.56.2 and upstream main do not coalesce them, so the README
recommends an explicit `hyprctl reload config-only` after such bursts.

Check Lua syntax with `luac -p` and live errors with `hyprctl configerrors`.
Hyprland 0.56.2's offline `--verify-config` crashes on `hl.timer(...)`, including
an otherwise empty configuration, so it cannot validate this configuration's
recovery timer. Keep native timer behavior and recheck offline validation after
upgrading Hyprland.

## Session ownership

`/etc/profile.d/zz-session-mode.sh` runs on login shells (sorted last so the session
inherits every profile export). On TTY1, when `uwsm check may-start` passes, it
replaces the shell with `session-mode run`, so no prompt appears; other consoles,
SSH and UWSM's environment preloader fail that check. `~/.hushlogin` silences the
login banner.

The supervisor runs one session at a time in an owned foreground process group:
Hyprland via `uwsm start -e -D Hyprland hyprland.desktop`, or the DRM
`gaming-session` launcher. Desktop starts set `UWSM_SILENT_START=1` to suppress
UWSM's informational console output while preserving warnings and errors.
It retains the PAM/controlling-terminal session and
hands the foreground terminal to each child. SIGTTOU is ignored only while it
switches the foreground group, so sessions inherit default job control. It holds a lock on
`$XDG_RUNTIME_DIR/session-mode/current`, which records the running mode and owner
PID; `session-mode status` reports availability from that lock.

`session-mode desktop|gaming` atomically writes the one-shot `next` request and
signals its owner. A wake pipe and child pidfd wait for requests/exits without
polling. Requests fail without a supervisor; gaming requests then run
`gaming-session --check`, and invalid GPU/output settings leave the desktop
running. The supervisor stops desktop through `uwsm stop` and ready gaming through
`steam -shutdown`, with bounded waits and TERM/KILL of its owned process group
if graceful shutdown fails. Before Gamescope's readiness, or once the session
leader has exited, it skips `steam -shutdown`: Steam's launcher starts a new
client when none is running. Without a request it starts the desktop. Any
gaming exit, including Steam Exit, a crash or startup failure, therefore returns
to Hyprland, and gaming never survives logout or reboot. Requesting desktop from
desktop is Reload. Startup discards stale requests. The latest request picks the
next session, so one made while a session stops or during a retry delay
replaces the pending choice rather than starting and stopping it.

Gaming passes a pipe to Gamescope's `--ready-fd` through `SESSION_MODE_READY_FD`;
no readiness within 45 seconds, or EOF without readiness, stops gaming and returns to desktop.
Data after the readiness line is the launcher's report that Steam exited: the
supervisor then gives Gamescope the graceful-stop wait to follow before
TERM/KILL, without `steam -shutdown`. EOF after readiness only ends the watch.
Desktop exits within 5 seconds without a request retry with a capped backoff.
SIGTERM/SIGHUP stop the current session and end supervision; Ctrl+C is ignored
by the supervisor only. Child sessions start with clean display/socket variables.

Steam's `-steamos3` exposes the `steamos-session-select` hook, installed in
`/usr/bin` and routed to `session-mode desktop`. See the
[gaming launcher architecture](../../gaming/gamescope-session/ARCHITECTURE.md).

`tests/test_session_modes.py` runs the production supervisor and Steam hook with
isolated compositor and Steam executables, covering transitions, Reload, Steam
exit, gaming failure/timeout, stops before readiness, requests made during a stop,
failed stops, and the desktop default of a new login. With the real launcher and
a fake Gamescope that follows 3.17's readiness, descriptor and lingering
behavior, it also covers Steam exit reports. A pseudo-terminal test
checks foreground handoff and inherited signal dispositions; other tests keep
the supervisor off the terminal running them.
`test_boot_and_session.py` checks autologin provisioning and the TTY1 profile
gate. Neither replaces a real DRM/Steam round trip on the installed hardware.

Native shutdown can still fail inside packaged compositors. Aquamarine 0.15.1's
multi-output teardown can dereference a cleared connector in
`flushAsyncCommitEvents()` ([upstream issue](https://github.com/hyprwm/aquamarine/issues/383)).
Gamescope can linger after Steam exits; a related DRM teardown stall is tracked
[upstream](https://github.com/ValveSoftware/gamescope/issues/2287). The supervisor's
bounded stop and process-group cleanup remain necessary even after a successful
Steam startup, including after Steam exits on its own. A successful return proves
session recovery, not a clean native compositor shutdown.

## Desktop integration

`workspaces.lua` owns navigation policy for shortcuts, gestures and the bar.
Shortcuts use the active monitor; bar buttons pass their output's numeric monitor
ID, resolved against `hl.get_monitors()`. Native monitor selectors, in
`hl.get_monitor()` and dispatcher `monitor` fields, accept a bare number only
below the active output count, while disabled or replugged outputs keep their IDs
reserved, so dispatches name the output. Regression coverage lives in
`tests/test_desktop_workspaces.py`, whose fake models these native lookup, monitor
and timer contracts.

`bindings.lua` assigns descriptions to keybinds with `hl.bind`'s `description`
flag. Hyprland exposes those labels in `hyprctl -j binds`, which feeds the
Keyboard drawer's live shortcut reference. Keep descriptions concise and
user-facing when adding or changing bindings; undocumented callbacks fall back
to a generic action label.

Hyprland moves workspaces intact off removed, disabled and mirrored outputs,
carries their floating windows along and returns them when their output
reconnects. `DesktopWorkspaces.recover()` covers what that leaves behind, such
as after a mode, scale or rotation change: mapped, non-hidden, non-fullscreen
floating windows wholly outside every usable output's work area are fitted into
their workspace's output, else the focused or first usable one, including
reserved edges, scale and rotation. `hl.get_monitors()` lists enabled outputs
only (`HL.Monitor` has no `enabled` field); mirrors and Hyprland's invisible
`FALLBACK` are excluded. Reachable floats and tiled scrolling columns keep their
placement. Recovery runs once, 150 ms after the last `monitor.layout_changed`,
and not on configuration load. A fired one-shot `hl.timer` is released and
cannot be re-armed, so a repeating timer disarms itself after each run. The
policy launches no helper and polls nothing.
The Quickshell display service owns re-enabling a disabled panel when no real
independent output would survive; it excludes `FALLBACK` from its inventory.

`desktop-screenshot` selects with slurp (`-d` for areas, `-r` over visible window
boxes) before capturing with grim, so cancelling writes nothing and leaves the
clipboard alone. Window boxes come from `hyprctl -j` and are clipped to their
monitor's logical area, keeping scrolled-off columns out of the image. Whole
displays use `grim -o NAME`, which captures at native resolution with the
output's transform. Saved images are copied to the clipboard; without the editor,
a notification confirms the file. The default editor launches as
`ksnip --edit` with the literal image path; `DESKTOP_SCREENSHOT_EDITOR=satty`
selects the alternative. The Ksnip preferences disable its tray icon and
minimize/close-to-tray behavior. User geometry and annotator preferences stay
outside the managed defaults. Bindings start the helper through `uwsm-app`, like
other applications, so an editor runs in its own unit.

The helper reads `$XDG_CONFIG_HOME/quickshell/desktop/screenshot-editor` (`on` or
`off`, default `on`) for ordinary capture modes. `edit`/`--edit` force editing;
`--no-edit` forces raw capture. Print and Win+Shift+S use `region` so the shared
preference applies; Win+Shift+Print explicitly passes `--no-edit`.
The shared `screenshot-save` preference also defaults to `on`; explicit
`--save`/`--no-save` override it. Clipboard-only mode overrides editing; grim's PNG
stdout is buffered in Python memory and checked before calling wl-copy, so a
failed capture cannot replace the clipboard. No screenshot directory or temporary
image is created, and this path sends no notification, including on failure.

The Capture drawer uses `output --output NAME` or `region`, plus `--report` and
explicit editor/save flags, to read back a saved image path (or `clipboard`) and
optionally start the editor as a `uwsm app` service, so capture is not busy
until it closes and a shell restart cannot kill it. Area selection reads
stdin from `/dev/null`; slurp would otherwise wait on any open non-terminal
stdin. Missing whole-display
images are failures rather than selection cancellation. The drawer owns delay
and dismissal timing; the helper performs the capture immediately.

The recording shortcut invokes Quickshell's `desktop:record-region` global
shortcut. It selects an area through Slurp when idle and stops an active recording.
The shell owns recording preferences and the supervised recording service; see
[Capture architecture](../quickshell/ARCHITECTURE.md#capture).

Night light uses the packaged `hyprsunset.service`. Its enablement belongs to the
Display drawer toggle, so provisioning does not enable it globally. The native
`hyprsunset.conf` asset defines the filter and optional profiles.

Hypridle calls `desktop-idle blank` to turn off only unprotected monitors. Lock
and suspend listeners use `desktop-idle allow-lock` and `allow-sleep` as their
conditions, retrying every ten seconds. The wrapper invokes the Quickshell display
helper, which owns the session-local Keep awake leases and independent temporary
sleep/locking pauses; it exits 0 to allow, 1 to defer and 2 on failure. Python
also exits 1 when the helper crashes, so the wrapper trusts status 1 only with
the helper's printed `defer`. Helper failures allow locking but block automatic
suspend. See [the display architecture](../quickshell/ARCHITECTURE.md#night-light-and-keep-awake)
for liveness and hardware matching. Existing application inhibitors are respected.
Manual lock and before-sleep commands remain unconditional. Idle and system resume
turn every display on with the DPMS dispatcher, then emit
`desktop-displays-changed` so the display service reapplies adjustments it skipped
while panels were dark.

`monitors.lua` registers the native `monitor.layout_changed` Lua callback and
forwards it with `hl.dsp.event("desktop-displays-changed")`. Quickshell consumes
that notification through its existing Hyprland IPC subscription to save display
preferences without polling. This callback launches no process. Lua subscriptions
are rebuilt by Hyprland on config reload. Persistence and restoration belong to
[the display service](../quickshell/ARCHITECTURE.md#displays).
